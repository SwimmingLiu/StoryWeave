# HTML 视觉复核修订方案

批准稿保持不变。版式、字体、素材和连线决定写入视觉计划，renderer 只消费计划与批准内容。阶段顺序为产品实现与回归、验收 Skill 维护、真实驱动与人工复核。

| 问题 | 实现 | 证明方式 |
| --- | --- | --- |
| 正文和节点孤字 | 共用中文分词排版，标记短词但不插入可见文字 | 浏览器字符行框、短词行框，故意破坏后的阻断测试 |
| 流程箭头与编号冲突 | 独立节点轨道，按实际 DOM 边界生成路径 | 连线采样与字符框碰撞检查，端点与节点距离 |
| 比较偏向末列 | 计划明确 neutral，比较值共用文字颜色和字重 | 浏览器逐行对比各数据列的视觉权重 |
| 杂志与瑞士风过近 | 杂志侧栏图文与上下结构图；瑞士通栏示意图与左右结构图 | 同内容逐页、整套与双视口截图 |
| 图片作用不明确 | 以同组信息块的拥挤与疏朗排布说明版式选择 | 人工检查与论点的联系；素材不包含新事实、文字或数据 |

在 1280×720 舞台上保留正文 24px 下限和底部安全区。390×844 继续等比显示，用于整体预览；本轮不改变竖屏的页面模型。每次生成均比较批准稿 SHA-256，真实浏览器 QA 要求 blocking 与 degraded 为零。
