# 视觉语义评测与生成前检查

视觉改动应让当前内容更容易理解。更换阅读方向、增加版式种类或拉开主题差异，都不能单独证明改善。已批准的文字、数字、关系和备注继续受内容合同保护。

## 从 unslop 采用的方法

本项目借鉴 Damir Sokolovsky（[@heydamir](https://x.com/heydamir)）的[视觉版 unslop](https://github.com/heydamir/unslop/tree/1d13095e4bef6ad6c74f1dd828d84c4ba309a4dc)，固定版本为 `1d13095e4bef6ad6c74f1dd828d84c4ba309a4dc`，许可为 [CC BY 4.0](https://github.com/heydamir/unslop/blob/1d13095e4bef6ad6c74f1dd828d84c4ba309a4dc/LICENSE)。以下是面向演示文稿的改编，保留作者署名；没有覆盖本机同名的文字润色 Skill。

采用其局部问题局部修整、从内容确定方向、用截图复核、删除无关装饰的方法。图片必须能说明它与当前主张的联系；去掉装饰后，也要检查是否仍是可套用于任意主题的通用模板。来源为[主流程](https://github.com/heydamir/unslop/blob/1d13095e4bef6ad6c74f1dd828d84c4ba309a4dc/skills/unslop/SKILL.md)、[视觉信号](https://github.com/heydamir/unslop/blob/1d13095e4bef6ad6c74f1dd828d84c4ba309a4dc/skills/unslop/references/signs.md)和[素材语义](https://github.com/heydamir/unslop/blob/1d13095e4bef6ad6c74f1dd828d84c4ba309a4dc/skills/unslop/references/visuals.md)。

网页导航尺寸、移动端重排、禁用所有斜体或固定字重等 UI 规则，不替代演示文稿的既定主题、固定 16:9 舞台和内容合同。颜色、卡片或居中本身不构成 AI slop，须说明它在当前页面造成的具体问题。图片工具与回退继续遵守用户已有授权。

## 生成前

开始生成或优化页面时，先在工作区的 `visual-intent.json` 记录以下内容，再选构图。维护既有产物时只作回顾记录，不能倒填为修改前已完成。

| 字段 | 需要说明 |
| --- | --- |
| audience_and_task | 观众要理解什么，展示距离和阅读条件是什么 |
| claim | 本页已批准的主张 |
| representation | 表、图、流程、图片分别承担什么信息，阅读起点和终点在哪里 |
| findings | 实际问题、截图位置与影响；区分无明显问题、局部问题、广泛问题 |
| preserve | 现有清楚的关系、顺序、字体角色和品牌要素 |
| proposed_change | 解决问题所需的最小改动及其验证条件 |

局部断词先修词组、文本宽度或节点容量。若横向分流与汇合清楚，先保留方向，不为区分主题另造纵向结构。没有可指出的问题时允许保持原版。发现批准文案本身有问题时另记为内容问题，不以视觉优化为由擅改。

生成过程中按内容职责检查：

- 视觉焦点落在主张、证据或关系上。同等强调、无意义标签、装饰图标、发光边框和占位图形可能争夺注意力，须指出实际位置和后果。
- 图表的颜色、粗细、大小和位置应有可解释含义。中性比较不暗示某列获胜；没有依据的数字卡、微型图、趋势箭头或假界面不能填补空白。
- 连线应让观众看出起点、终点、方向和分支。端点正确，但路线过平、绕远、拥挤或产生假汇合，仍可能损害理解。
- 素材帮助解释当前内容。通用球体、科技线路、机器人、拼贴、纸张纹理或矩形面板，只有承担明确语义时才有保留依据。技术图解可用原生 SVG，不必换成照片或生图。
- 留白区分信息组，字号适合观看。不能以极小文字维持整齐，也不能把大量空白与松散节点自动称为高级感。
- 全套可共用清楚的构图。节奏由内容任务决定，不强求每页不同，也不强求两种主题在每个图上使用不同方向。

## 逐页与整套比较

保留真实基线，两侧批准稿相同，使用相同视口、字体环境与截图尺寸。先看 A/B 页面并记录观察，再查看版本对应关系。A/B 位置交替只减少位置暗示；评审者看过旧版本时必须声明，不能称为独立盲测。

| 维度 | 判断问题 | 可核对的依据 |
| --- | --- | --- |
| meaning | 图像与编码是否支持批准主张，是否产生新事实或误导 | 对象、图例、强调与文字主张的对应 |
| reading | 观众能否找到重点并顺序阅读 | 第一焦点、标题正文层级、具体断行、文字与背景 |
| relationships | 轴、方向、分组和分支是否清楚 | 起止节点、箭头路径、比较列、空间邻近与假汇合 |
| composition | 对齐、比例和间距是否帮助组织信息 | 对齐线、信息组距离、节点跨距、图文分配 |
| specificity | 素材与细节是否属于当前内容 | 无助于主张的图块、装饰标签、重复卡片、空洞隐喻 |
| coherence / rhythm | 全套是否稳定，节奏是否适合内容 | 字体角色、强调逻辑、图表编码、连续八页的疏密 |

每个维度填写 A 更好、B 更好、持平或不确定，并写出截图依据。“更现代”“更有设计感”“风格更不同”不能作为依据。结论为 improved、unchanged、regressed 或 unreviewed。任一维度更差都会阻断接受，整套改善不能抵消某页退步，不计算平均审美分。

另记 AI slop 观察。没有发现时说明检查了什么；存在时给出具体图形或文本、所在版本及影响。blocking 表示影响理解或含有无依据的视觉内容；advisory 是需判断的局部信号。不确定时保留 unreviewed。

## 证据与状态

`visual-review.mjs` 保存图片、批准稿与生产者绑定，创建逐页 A/B、整套视图及空评审模板。它强制覆盖、证据一致和失败规则，不会从像素自动推导审美判断，也不以填写 JSON 证明已经看图。署名的人或视觉模型须实际查看，并记录熟悉程度与限制。

技术 QA 与视觉接受分别报告。缺少评审为 needs-review，任一退步为 regressed，均不能宣称优化完成。全部页面与整套均不退步才为 accepted。全部持平可以接受，但不能宣称改善。Bento 包装或独立安装通过，也不能覆盖上游视觉不通过。

默认比较桌面 1280×720；竖屏另做几何与播放检查，不由此声称小屏正文可读。使用保留截图时标记 retained-browser-evidence，不称为本轮重新打开浏览器。浏览器限制按 Skill 的 launch 规则保留。
