# 统一 StoryWeave 共享核心并改进 HTML 构图

## 背景与问题

StoryWeave 的两个生成器曾分别维护内容、主题公共规则和文件工具，编排与 Express 又重复校验输出。HTML 主要依赖通用页面骨架，`exact_text` 字符串不足以准确表达比较轴、方向或指标来源。发布副本和源码容易漂移，生产者 QA 也需要绑定实际页面，防止旧报告批准改动后的文件。

## 解决范围

将公共内容与产物规则集中到 `src/core/`。确认内容使用 schema 4，HTML 与 Imagegen 分别拥有绑定内容修订的 schema 1 私有计划。两个生成器共享事实，各自规划视觉；Bento 只消费已通过当前生产者 QA 的成品。

HTML 使用比较、流程、指标、关系图和观点的原生布局，保留固定舞台与可编辑文字。修复导航按钮保留焦点时空格触发两次的问题，并在独立页与画廊中检查准确文字、关系边、双视口和资源。

设计案例使用完整元信息、分析与标签索引。所选参考捕获到项目内，HTML 保存具体应用，Imagegen 任务携带真实工具输入路径，结果收集保存实际调用与返回图片。当前生成验证样本与后续人工案例收录分别验收。

从唯一源码生成四个独立 Skill 运行包，校验字节清单与安装备份。全局 Skill 自带 Bento，适配报告与生产者报告分别保存。通过[七类功能地图](../../.agents/skills/verify-storyweave/features/README.md)驱动真实 CLI 与 Chromium，保留清理后可读证据。

## 验收条件

- 内容确认与视觉重规划分开，v4 换主题不改确认稿；旧 v2、v3 继续按原语义构建。
- 公共产物规则在直接 Express 与全局入口一致，旧 QA 拒绝内容、计划、页面、素材或证据变更。
- 相同内容与主题的前后截图能说明构图改善，整套缩略图保留人工视觉结论。
- 实际生图附图记录能对应选中参考与返回 PNG，逐页复核不冒充 OCR。
- 独立安装包使用自己的应用模块和资源，包内副本与源码一致，安装更新可恢复。
- 全量测试、七类用户路径与清理后证据校验有当前源码记录，未执行项目如实保留状态。
