# 演讲与分享稿主题参考

从[主题参考画廊](../assets/reference-library/index.html)查看同风格的多张内容页，先按场景筛选，再按观点、流程、对比或数据定位页面。技术分享优先显示。[来源目录](../assets/reference-library/catalog.json)逐页记录作者、固定版本、样式说明、提示词范围与视觉查验。[页型覆盖](../assets/reference-library/coverage.json)从实际页面生成。

当前收录 18 种风格、41 张内容页；这些参考已对应到 14 个生成方向，生成器另加入四套已选原创架构主题，合计 23 套候选主题。页型按实际图片标注，同一张图可有多种职责，但图片数量只计一次。

## 按内容页选择风格

以现有青蓝主题为例，一页应当同时容纳标题、主张、内容分组和可顺着讲解的关系。先看一套风格如何解释内容，再看材质与装饰。只提供封面或独立物体的图片，不能证明适合整套演讲。

`description` 说明视觉方向，`presentation_fit` 说明分享场景。`pages` 是实际内容页集合，每页的 `roles` 与 `role_notes` 说明画面能证明的职责。页型筛选只显示匹配的实际页面，不用同一张图重复填充缺失页型。架构说明独立标注，目录层级和箭头不自动算作流程。

同一页确实含有比较和数据时，可以分别记录这两项用途，但图片数量只计算一次。画廊列出各风格已有的页型与待补项，封面、章节和装饰数字不作为内容页证据。扩成生成主题前，仍需用同一份中文内容检查跨页连续性与现场可读性。

普通字阶、网格、卡片、表格、代码和准确数据优先使用 HTML、CSS、SVG。Imagegen 参考关注连续的技术插画、手绘笔触、玻璃光照、水墨或黏土场景。仅有同色卡片的页面归 HTML；采用某种材质，不意味着每一页都必须整页生图。

## 使用来源与参考图

1. 先查看页面的 `source_url` 和实际原图，读 `prompt_url` 对应的说明。`prompt_scope` 区分样张原提示词、演讲大纲、风格说明和工具系统提示词；工具提示词不作为每张图片的原始请求。`provenance_note` 保留来源声明，适配模型列表不等于逐图运行记录。
2. 选择主体、配色、材质和内容组织方式。参考文字、数据、代码、印章和水印不进入新项目的 `exact_text`。必要图形关系由项目资料确定。
3. 根据来源的图片取用范围，将选定原图保存到项目，保留作者、链接与用途。将实际文件附到工具调用。v4 使用设计案例捕获与 receipt；旧版项目由 Agent 附图并保存调用记录。
4. 按 16:9 页面重新安排本项目的真实内容。检查中文标题、必要标签、图形关系与留白。只提及图片名称时记录为 `prompt-only`，不能当作实际附图。

这些条目是外部内容页参考，已按[主题映射](../assets/themes/reference-theme-map.json)对应到生成配方，主题状态继续独立维护。`continuity` 区分同一套演讲、来源中的同风格集合与多个来源的视觉方法。合并为同一视觉方向，不表示原图本来就是同一套演讲；新稿需统一字体、配色、角色和图形语言。

来源不足、只有单页或来自历史仓库时，在 `limits` 与 `source_status` 保留范围。数据页只提供材质和内容组织参考，原图示例数值不进入新稿；真实数值和比例继续由项目资料及原生图形保证。画廊从原始来源加载图片，不捆绑第三方原图。

## 离线查看

远程画廊的每组首图直接加载，其他内容页展开后加载。图片失败时显示重试入口；点击已加载图片可放大。

仓库维护时可生成独立的离线查看产物，缓存原始图片并内嵌到 HTML。以下命令从 StoryWeave 仓库根目录运行，需要 Python 的 Pillow；缓存只保存在指定查看目录，不进入 Skill 分发包。

```bash
python3 scripts/cache-presentation-references.py --cache tmp/presentation-reference-viewer
node scripts/build-presentation-reference-gallery.mjs --cache tmp/presentation-reference-viewer --out tmp/presentation-reference-viewer
```

打开 `tmp/presentation-reference-viewer/index.html`。检查缓存时，在第一条命令后加 `--check`；核对离线 HTML 时，在第二条命令后加 `--check`。缓存损坏或缺图时返回失败，不生成不完整的离线图库。

仓库 CI 会重新准备全量原图，检查解码、字节一致性、离线显示、筛选、大图和重试。技术检查与实际视觉评审分别记录；参考图库维护后需核对对应提交的 CI 结果。
