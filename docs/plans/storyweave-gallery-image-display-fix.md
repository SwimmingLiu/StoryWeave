# 修复参考图库图片显示

## 问题

参考目录已有 41 张远程图片，但图库依赖浏览器联网加载，并将多数图片设为延迟加载。缺少失败提示时，图片没有显示会表现为空白。已抽查的四个原始地址均返回有效 WebP 图片，不能据此把问题归为链接失效。

## 方案

每种风格的首图直接展开显示。其余内容页在展开时立即请求图片，失败时显示图片来源和重试入口。保留原来的目录、页型筛选与来源归因。

为本地查看生成独立离线 HTML。原始文件只缓存在项目查看产物目录，保持字节与来源记录，不复制进四个 Skill 的分发包。离线 HTML 内嵌图片后不需要外部图片请求。

## 验收

- 41 个源文件可读取并核对图片格式、尺寸与哈希。
- 离线 HTML 的 41 张图片全部使用内嵌数据，解码后与缓存原文件逐字节一致。
- 首图直接显示，折叠页展开加载，失败状态和重试有实际入口。
- 观点、流程、对比和数据筛选保持原有语义。
- 全局资源增量同步，主题、CLI 和工作流文件不变。
- 本地文件的浏览器导航已被工具安全策略拒绝，不改用其他浏览器导航绕过；显示检查与未覆盖范围分别记录。

## 检查结果

41 张原图均可完整解码，离线 HTML 的图片字节与缓存哈希一致。每组首图共 18 张为直接加载，六项状态与筛选逻辑检查通过。独立安装和全局资源核对通过，121 项现有回归通过。真实浏览器渲染受本地文件访问策略限制，记录为未验收。证据保存在 `tmp/presentation-gallery-display-fix/verification.json`。
