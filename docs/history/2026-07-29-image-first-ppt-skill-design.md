# Image-first PPT Skill 设计

## 目标

将现有 `create-editable-ppt` 改为整页生图优先的 PPT Skill。保留内容规划、八套主题、素材溯源、逐页 Review 和多格式导出；移除浏览器中的可见文字编辑及以 HTML/CSS 负责页面视觉排版的路径。

最终页面是一张 16:9 位图。用户修改页面时，修改结构化内容或生图提示词并重新生成该页，而不是编辑文字框。

## 完整流程

```text
用户资料
  -> 输入检查与页数确认
  -> 生成 PPT 内容草稿
  -> 确认中心含义、叙事逻辑和逐页内容
  -> 选择主题
  -> 编译每页 imagegen 提示词
  -> 生成整页图片
  -> 文字、构图、主题和事实检查
  -> 只重生成失败页
  -> HTML 预览 / 图片式 PPTX / PDF / PNG
```

## 核心架构

### 内容层

生图前先生成 `outline_draft.json` 和对应的 `outline_preview.html`。这版 PPT 内容草稿必须完整包含：

- 中心含义：整套 PPT 最终希望观众理解、记住或采取行动的一句话；
- 叙事逻辑：开场、问题、洞察、方法、证据与行动之间如何递进；
- 建议页数和每一页在叙事中的作用；
- 每页的页面目的、一句话主张、准确可见文字、证据或素材、页面角色以及与下一页的衔接；
- 尚缺资料、需要用户确认或不能由生图模型虚构的内容。

`outline_preview.html` 以“整体叙事在前、逐页内容在后”的方式供用户审阅。用户可以直接要求修改中心含义、叙事顺序、页数或某一页内容。草稿未确认前，不得选择最终视觉主题、编译提示词或调用生图。

草稿确认后，将其固化为 `deck_spec.json`，作为后续生成的唯一内容源。它保存受众、目的、中心含义、叙事逻辑、页序、每页主张、必须准确出现的文字、证据、素材要求和演讲备注，不描述具体 HTML 布局。

### 主题层

保留八套去重主题：

- `business-minimal`
- `editorial`
- `swiss-grid`
- `launch-tech`
- `data-consulting`
- `academic`
- `brand-bold`
- `premium-dark`

每个主题从 CSS token 改为生图配方，至少包含：艺术方向、构图语法、色彩、字体气质、图片语言、材质、适用页面、禁止项和主题一致性锚点。主题之间不能只有颜色差异。

### 提示词编译层

每一页生成一份结构化提示词，采用 `productivity-visual` 用例，明确：

- 16:9 演示文稿整页图片；
- 页面角色和单一主张；
- 必须逐字出现的文字；
- 主题配方和本页构图；
- 图片主体、留白、信息层级；
- 禁止水印、额外文字、品牌标识、密集 UI 卡片和无关装饰。

提示词、模型、尺寸、质量和重试记录写入 `generation_manifest.json`，便于复现和逐页返修。

### 生图层

默认调用 `$imagegen`。宿主内置工具可用时优先使用；本环境使用用户确认的 CLI 兜底路径，通过命令级环境变量映射本机 `OPENAI_SUB_*` 主配置，失败时切换 `OPENAI_SUB_FALLBAK_*` 备用配置。任何密钥都不得写入日志、提示词、产物或提交。

默认模型为 `gpt-image-2`。正式页面使用 `2048x1152`，首轮质量为 `medium`；只有文字错误、构图失衡或主题漂移的失败页才定向重试，必要时提升到 `high`。

### 输出层

- `outline_draft.json`：尚未确认的中心含义、叙事逻辑和逐页内容草稿。
- `outline_preview.html`：供用户确认和提出修改的 PPT 内容草稿预览。
- `slides/*.png`：最终整页图片。
- `index.html`：仅负责画廊、翻页、全屏预览和下载，不承担页面排版。
- PPTX：每页放置一张铺满画布的图片。
- PDF：按页封装最终图片。
- `generation_manifest.json`：提示词与生成溯源。
- `qa_report.json`：逐页检查与返修结果。

## 修改与兼容

- 移除 `contenteditable`、文字覆盖、拖拽排序写回页面、浏览器编辑状态及 HTML 反向解析。
- 保留逐页顺序、跳过、审核和重新生成能力。
- 将原先零散的“逐页主张确认”升级为完整内容草稿 Gate；任何生图调用都必须发生在草稿确认之后。
- 当前目录暂时保留，避免已有文档引用失效；Skill frontmatter 名称和界面文案改为 `create-image-ppt`。
- 旧 HTML 主题样例保留为迁移参考，不再作为默认生成结果。

## 异常处理

- 用户资料缺失：列出缺失项，只处理可读取内容，不猜测。
- 页数超出资料承载能力：提出缩减页数，不用空洞页面凑数。
- 用户尚未确认内容草稿：停留在草稿阶段，只修改中心含义、叙事或逐页内容，不提前消耗生图调用。
- 必须准确呈现的事实图、产品界面或实验数据缺失：阻塞该页生图，要求真实素材。
- 生图失败：主配置失败后使用备用配置；仍失败则记录错误并停止该页，不生成伪成功占位。
- 文字生成错误：缩短文字、强化逐字约束并仅重试该页；连续失败则将页面标记为未通过。
- 主题漂移：使用主题锚点和同主题已通过页面作为参考，定向重生成。

## Review 与 QA

每页至少检查：

- 准确文字是否完整、无错字、无额外文字；
- 主张与用户确认的页表是否一致；
- 图片是否符合素材要求且不伪造事实；
- 构图、层级、对比度和裁切是否适合投影；
- 是否符合所选主题，而不是通用 AI 海报；
- 是否存在水印、乱码、重复元素或异常肢体；
- 全套页面的主题一致性和相邻页面节奏。

存在 blocking 项的页面不得导出。返修只针对失败页，已通过页面不重复生成。

内容草稿还必须先通过以下检查：中心含义是否单一明确；叙事是否存在跳跃或重复；每一页是否推动主线；准确文字是否适合投影；证据和素材是否足以支撑主张。未通过的草稿不得进入生图阶段。

## 样例范围

使用同一套“AI 原生知识工作流”内容，为八个主题各生成三页：

1. 封面：`AI 原生知识工作流`
2. 核心内容：`四个动作，让信息持续产生价值`
3. 结束页：`先重做一条高频流程`

共生成 24 张图片，并提供统一浏览器画廊，支持按主题和页面角色对照查看。

## 验收标准

- Skill 默认路径明确要求整页生图，不再推荐可编辑文字。
- 生图前能够生成并展示一版包含中心含义、叙事逻辑和逐页内容的 PPT 草稿，并设置明确的用户确认 Gate。
- 八套主题均有独立提示词配方和三张实际样例。
- 24 张图片全部为 16:9，文字和主题检查通过。
- 画廊在桌面和移动视口无破图、溢出或遮挡。
- 测试和 Skill 结构校验通过。
- 文档、日志和生成产物不包含任何密钥。
